# Evidence-Based AI Root Cause Analysis for Microservices (MVP)

A fully functional, auditable root cause analysis (RCA) platform for distributed microservices. Unlike black-box diagnostic tools, every verdict generated by this system is backed by real OpenTelemetry telemetry, a mathematical scoring formula with documented weights, and an auditable confidence score. Recovery actions are never executed autonomously — human operators maintain complete control via an approval layer.

---

## Key Differentiators

1. **Auditable Scoring, Not Guesswork**:
   $$\text{score}(c) = 0.35 \times \text{temporal}(c) + 0.40 \times \text{dependency}(c) + 0.25 \times \text{severity}(c)$$
   Every confidence score is mathematically derived from the gap between the top and second-ranked candidates. No numbers are hardcoded or fabricated.

2. **Dynamically Derived Dependency Graph**:
   The topology is built automatically by parsing distributed trace parent-child spans in PostgreSQL. It is never hardcoded.

3. **Grounded AI Reasoning (Claude Sonnet 5)**:
   Claude is constrained via system prompts to cite *only* the telemetry evidence, z-scores, and topology paths provided in the payload.

4. **Human-in-the-Loop Safety Gate**:
   AI recommendations enter an `awaiting_approval` state. Recovery *cannot* execute without an explicit cryptographic/operator audit log entry.

5. **Closed-Loop Docker Recovery & Verification**:
   Restarts affected containers via the Docker Engine API and polls health checks every 2 seconds for up to 30 seconds before declaring resolution.

6. **Single-Screen "Control Room" Interface**:
   Custom design tokens (deep graphite `#14171C`, hairline borders `#2A2F38`, signal blue `#5B8DEF` for AI accent, Inter for UI chrome, IBM Plex Mono for all measured metrics). Features a single deliberate 1.2s color animation on node resolution.

## Scoring Formula & Weights Rationale

### 1. Scoring Formula
$$\text{score}(c) = w_1 \cdot \text{temporal}(c) + w_2 \cdot \text{dependency}(c) + w_3 \cdot \text{severity}(c)$$

*   **$w_1 = 0.35$ (Temporal Score)**:
    Earlier anomalies are more likely root causes. However, timing alone in distributed systems is noisy due to network jitter and clock skew, so it is weighted below dependency proximity.
*   **$w_2 = 0.40$ (Dependency Score)**:
    Upstream proximity is the strongest causal signal. A failure in an upstream dependency (`payment-service`) propagates downstream to cause timeout symptoms in `order-service` and `frontend-gateway`.
*   **$w_3 = 0.25$ (Severity Score)**:
    Normalized from the rolling z-score magnitude ($\frac{|z| - 3}{10}$). Extreme deviations are prioritized, but high severity alone doesn't prove causation.

### 2. Confidence Derivation
*   **Single Candidate**: $\text{confidence} = \min(95, 50 + \text{severity\_score} \times 50)$
*   **Multiple Candidates**:
    $$\text{gap} = \text{score}_{\text{top}} - \text{score}_{\text{second}}$$
    $$\text{confidence} = \text{clamp}\left(\frac{\text{gap}}{\text{score}_{\text{top}}} \times 100, 30, 95\right)$$
*   **Floor (30%)**: If the engine ran against real anomalies, there is non-zero signal.
*   **Cap (95%)**: Distributed systems are inherently stochastic; absolute 100% certainty is unscientific.

### 3. Naive Baseline Comparison
Runs concurrently on every incident:
$$\text{root\_cause}_{\text{naive}} = \arg\min_i(\text{timestamp}_i)$$
Ignores the dependency graph entirely. The dashboard displays both side-by-side so operators can immediately see why the evidence-based engine correctly rejects naive first-arrival at the edge.

## Design System Tokens (Control Room)

*   **Background Base**: `#14171C` (deep graphite)
*   **Surface / Panels**: `#1C2129` separated by 1px hairline borders (`#2A2F38`), zero drop-shadows or rounded cards.
*   **Status Palette**:
    *   Healthy: `#5FBF77`
    *   Warning: `#E8A33D`
    *   Critical: `#E5484D`
*   **AI Reasoning Accent**: `#5B8DEF` (Signal Blue — visually distinct from system health so users never confuse AI opinion with system state).
*   **Typography Rule**:
    *   `Inter`: UI labels, headings, buttons.
    *   `IBM Plex Mono`: Every actual data value (metrics, timestamps, latencies, confidence %, z-scores).
